# Plan: Release v0.1.0 Cleanup And Publish

Bring the build to a first public release `v0.1.0` of `clericlvl2/combat-planner-v2`: 13th Age terminology, default names in forms, the open defects, geometry checks, a code-first repository, release automation, a rewritten author email, and publication.

Out of scope:
- hosting and deployment, a separate step after publication;
- the notice to Pelgrane / Fire Opal Media required by the 13th Age Community Use Policy, which the owner sends later;
- responsive 320 px / desktop layouts;
- pruning the screenshot set to a curated ~200, which happens when the responsive rework starts.

## Principles

- The code is the source of truth. A document stays only if it is a README for a person, or `CLAUDE.md` for an agent.
- Everything removed from the tree stays reachable under the tag `archive/build-v2`.
- Commit subjects from the first commit of this plan follow Conventional Commits and state the user-visible result, e.g. `fix(ui): empty combat title saves as "Combat Oct 19"`. They feed the changelog.
- Commit trailer: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Batch gate: `.claude/run/gate.sh` without the `check-commit` step; that script is removed in step 6.

## Execution

- Steps 1–5 are batches. Each gets a brief in `.claude/artifacts/briefs/`, its own worktree `../combat-planner-v2.wt/<batch>` and branch `agent/<batch>`, and one worker-bee. Each then goes through gate, merge and guard-bee, as in `CLAUDE.md` Integration.
- At most two batches run at once: 1 with 5, then 2 with 3, then 4.
- The orchestrator runs steps 6–8 on `master`.
- Stop points for the owner:
  - after step 6, to show the deletion diff;
  - before step 8.4, the first push to GitHub.

## 2. Batch `fix-13-default-names`: names never block saving

Shared rules:
- Input is trimmed. An empty or whitespace-only field is empty.
- The create button is always enabled.
- The error keys and their error stories are removed.
- Domain schemas keep `min(1)`; they validate the substituted value.

Combat (`screens/CombatList/CombatFormSheet/CombatFormSheet.tsx`):
- Create: the placeholder is `t('defaultTitle', { date })`, where `date` is `new Intl.DateTimeFormat(locale, { day: 'numeric', month: 'short' }).format(now)`. An empty field saves the placeholder.
- Edit: an empty field saves the previous title, and the placeholder shows the previous title.
- i18n:
  - new key `CombatFormSheet.defaultTitle`: en «Combat {{date}}», de «Kampf {{date}}», es «Combate {{date}}», fr «Combat {{date}}» (added to `allow-same.txt`), ja «{{date}}の戦闘», ru «Бой {{date}}»;
  - removed: `CombatFormSheet.titleRequired`, `CombatFormSheet.titlePlaceholder`.

Unit (`organisms/UnitForm/UnitForm.tsx`):
- The prop `roleCounts` is replaced by `unitNames: readonly string[]`; `CombatScreen.tsx` passes the names of `combat.units`.
- Add: the default is `t('defaultName', { role, n })`, where `n` is the smallest integer ≥ 1 such that no unit is named exactly that string. An empty field saves the default.
- Edit: an empty field saves the previous name, and the placeholder shows the previous name.
- Removed: `nameError` state and the key `UnitForm.nameRequired`.

Preset (`screens/Library/PresetFormSheet/PresetFormSheet.tsx`):
- Create: an empty field saves `t('namePlaceholder', { role })`, e.g. «Враг 1».
- Edit: an empty field saves the previous name.
- Removed: the key `PresetFormSheet.nameRequired`.

Unchanged and still required: SignIn, SignUp and Account display name, and the hero name in `Heroes`.

The default is stored in the DM's language, as typed text.

Stories:
- The error stories of CombatFormSheet, CombatList, PresetFormSheet, Library and UnitForm are replaced by plays: an empty field plus the primary button calls `onSubmit` with the default, or with the previous name in edit mode.
- A UnitForm play covers the first free number: with units «Enemy 1» and «Enemy 3», the default is «Enemy 2».
- `TextField` and `Sheet` keep their generic error demos.

Acceptance:
1. No create or edit form for a combat, unit or preset disables its primary button or shows an error for an empty name.
2. The plays above pass, and the gate is green.

## 3. Batch `fix-14-open-defects`

First, a read-only check of every guard finding routed `→ fix-…` in the build progress file, section «Замечания guard-bee P2–P3, отложены», against the current code. The worker lists each item still reproducible in `REPORT.md` and fixes it in this batch.

Then the known open items:
1. HP history keeps the max at the time of the entry. `HpHistoryEntry` gets an optional `max`; `HistoryRow` shows `entry.max ?? current max`. Covered by a domain test and a story.
2. A combat copy is stored with `version 1`, and `PATCH /combats/:id` with an empty body does not bump the version. Covered by API tests.
3. `loadLog` for undo reads only the entries undo can reach (depth `LIMITS.undoDepth`), and `dmDocument` reads only the rows it returns (`log.ts:78-81`). Covered by API tests with a log longer than both bounds.
4. `hono-client.ts:330`: an SSE payload that fails `safeParse` is dropped and triggers a document refetch. A test sends a malformed event.
5. The player document in the SSE stream carries the DM's language, so a language change reaches players without a refetch. Covered by an API test and a client test.
6. `DmLocale`:
   - a test renders a DM route after a player route and asserts that the browser language is never applied to the first frame;
   - the locale is fixed before paint if the test fails.
7. Types and wiring:
   - `Link` in `@combat-planner/api` is renamed `PlayerLink`;
   - `LinkReissueResult` uses `generation`;
   - `ApiAppEnv.userId` is optional;
   - `requireUser` is applied once under `/combats`;
   - `hono-client.ts` no longer imports `hono/hono-base` or `hono/utils/types`.
8. Tests:
   - router wiring at `apps/web/src/pages.tsx:68` and `main.tsx:40`;
   - `project()` throws, built from a live combat in `events.test.ts:227`;
   - the surrogate-pair branch of `clampDisplayName`.
9. The e2e teardown marker key has one source. `NoteField.collapseRow` and `InitiativePopover.anchor` leave i18n: the stories use literals.

Acceptance:
1. Every item above is fixed and has the named test.
2. `REPORT.md` lists the routed findings checked, each with fixed / already fixed / not reproducible and file:line.
3. The gate is green.

## Day-to-day release flow (goes into README «Releases»)

1. Work on `dev`; CI runs on every push.
2. Open a PR `dev → main`; CI and e2e run. Merge with «Create a merge commit».
3. release-please opens or updates the PR «chore(main): release X.Y.Z» with `CHANGELOG.md` and `package.json`.
4. Edit the notes in that PR if needed, then merge it through admin bypass. That merge is the release button.
5. The tag, the GitHub Release and the Docker image are created, and `main` is merged back into `dev`.
6. Hotfix: branch `hotfix/<name>` from `main`, a `fix:` commit, a PR to `main`, then steps 3–5.
