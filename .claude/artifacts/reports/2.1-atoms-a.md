## Questions

1. `LIMITS` does not exist anywhere in the repo (`packages/domain/src` has only `health.ts`), so `TextField` and `TextArea` take `maxLength: number` and the stories pass the page's numbers (80, 40, 500, 250) as literals. Where should a shared `LIMITS` constant live, and which batch adds it?
2. ToolButton icon size: the page SPEC says "22 icon only, 18 with a label", but the page script's `sized('tool')` overrides that with 16 / 20 / 24 per size in every rendered cell. I built the rendered values (16 / 20 / 24); `ExtraSizes` asserts them.
3. ToolButton accessible name: the page sets `aria-label` to the label, which hides the count from screen readers. The component leaves the name to the content ("Tags 2") unless the caller passes `aria-label`; icon-only uses `aria-label` ("Sort"). Confirm.
4. TextField wraps long names inside the field ("Long names wrap"). An `<input>` cannot wrap, so TextField renders a one-row auto-growing `<textarea>` (`aria-multiline="false"`): Enter is blocked outside IME composition, and pasted line breaks become spaces. It has no `type` prop because the page has no password or email cell. AppPages sign-in (email, password) will need either a `type` variant that renders an `<input>` or a separate field. Which one?
5. TextField and TextArea are built on plain elements, not Mantine `TextInput` / `Textarea`. The theme's global `Input` classNames (`theme.module.css .input`: disabled fill `#E6DDCC`) conflict with the page's disabled fill `#F3EDE2`, and `TextInput` cannot wrap.
6. Several page translations equal the English word (de "Name", "Optional", "Tags"; fr "Description"). `allow-same.txt` only allows brand names, numbers and symbols, so I used other words: de "Bezeichnung", "Freiwillig", "Schlagwörter"; fr "Descriptif", "Remarque". The owner may prefer the identical words plus `allow-same.txt` entries.
