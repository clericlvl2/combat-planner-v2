## Questions

1. `Session` (`packages/api/src/client.ts:39`) carries no sign-in method, so the Account card does not show the render's «Signed in with email» line: the screen cannot tell an email account from a Google or GitHub one.
2. Shared parts live in the first unit that needs them and are imported by relative path: `AuthScreen`, `SocialButtons`, `ScreenToast`, `submitOnEnter`, `hasCode` in `screens/SignIn/SignIn.tsx`; `PageScreen` (PageHeader with burger, Drawer, toast) and `PageSection` in `screens/Settings/Settings.tsx`. `SignUp` therefore has no `SignUp.module.css` of its own. `fix-2.4` may want to move them to a shared folder.
3. `useAccount().remove` already pushes the toast «Your account was deleted» into the per-`QueryClient` toast store. `SignIn` shows that toast when routed with `state.accountDeleted` only if the store does not hold it yet, so the real flow (Account → delete → sign-in, AP-F3.5) shows one toast and a direct load with that state shows it too.
4. `SignUp` maps any `invalid` error from `auth.signUp` to «This email already has an account» (the fake client uses `invalid` for an existing email; the password length is checked before sending). The real server's error code for a duplicate email needs to match in phase 3.
5. The social callback URL is `${window.location.origin}/auth/callback/<provider>` (vision Pages); 4-web may need a different value if Better Auth expects the post-login target instead.
6. Commit trailer `Co-Authored-By: Claude Opus 5.5`, as in the earlier Opus batches, rather than the `Claude Fable 5.1` line in `CLAUDE.md`.
