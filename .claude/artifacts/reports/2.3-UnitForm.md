The cell stories are exported as `Extra<CellName>` with `name` set to the page label: `ExtraAnatomy`, `ExtraNewEmpty`, `ExtraNewFilled`, `ExtraFromLibrary`, `ExtraLibraryTagsSheet`, `ExtraLibraryFilteredPicked`, `ExtraEdit`, `ExtraLibrarySearchGob`, `ExtraLibraryNothingFound`, `ExtraMinimumValues`, `ExtraEdgeCases40CharacterNameRu`, plus the flow `ExtraFlowAddFromLibrary`. If the script learns to read `items`, these exports drop the prefix and the baselines must be renamed. That work belongs to fix-2.3 or the script owner.
2. Blank name. The page says "An empty name becomes a default name", and vision.md gives the default `<Type> N`. The brief says "a blank name blocks submit". Implemented rule:
   - In add mode, a completely empty field submits `<Type> N`, where N comes from the `roleCounts` prop plus 1.
   - A name that is only whitespace in either mode, or an empty name in edit mode, blocks submit. The field shows the red error "Enter a name" (the page script has `nameErr` for this).
   - Typed names are trimmed.
3. Vision.md (Unit → Form) asks for a hint that initiative is rolled at Start in setup and on add in Active. The page script computes `hint`, but no cell renders it and the render shows none, so it was not built. The brief's prop list has no prop for it either.
4. The brief lists `NumberField` × 3 for the defenses and `NumberField` for HP. The page's SPEC says "Stepper M for Max HP, Temp HP, AC, PD, MD and Init bonus", and every form cell draws steppers, so all six are `Stepper`s. The value colours follow the page: ink fill for set values, muted text on white for fields not given in `value`.
5. Possible lower-level bugs, for fix-2.3:

   - `packages/ui/src/atoms/TextField/TextField.tsx:55`: `over` is `value.length > maxLength`, so the counter at 40/40 stays secondary. The UnitForm page turns it red at `>= 40` (`nameCountColor`).
