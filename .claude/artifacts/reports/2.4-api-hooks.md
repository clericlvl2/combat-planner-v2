## Questions

1. `@combat-planner/api` (`src/index.ts`) re-exports the server, so a value import from it in the browser fails (`node:crypto` from `link/token.ts`; Storybook stories stop loading). The `api client` commit adds the subpath export `"./client": "./src/client.ts"` to `packages/api/package.json`, a path outside the brief's list; `packages/ui` imports `LOCALES`, `ApiError` and the contract types from `@combat-planner/api/client`. `apps/web` will need a browser-safe export of `hono-client.ts` (for example `"./hono-client"`) in phase 4.
2. `packages/api/src/client.test.ts`, outside the brief's list, gets `providers` and `socialSignIn` in its stub `ApiClient`, because `tsc -b` fails without them.
3. `SOCIAL_PROVIDERS` and `SocialProvider` are not re-exported from `packages/api/src/index.ts`, which is outside the brief's list. They are available from `@combat-planner/api/client`.
4. `useCombat(id, viewer)` has no way to get the player's link token. The hook has two overloads: `useCombat(id, { kind: 'dm' })` and `useCombat(id, { kind: 'player', playerId }, token)`. The result is `{ combat, language, status, error, ended, dispatch }`, where `language` is the DM language from `PlayView` for a player and `null` for the DM.
5. The meaning of `Scenario.players` is not defined. It is `Partial<Record<CombatId, Record<PlayerId, DisplayName>>>` and is merged into the seeded combat's `players`. `Scenario.accounts` (`FakeAccount[]`: email, password, displayName, language) is added so sign-in and sign-up stories can succeed or fail. `emptyScenario` is signed in as `dm@example.com` / `correct horse battery`, with language `en`, no providers and connection `connected`.
6. `useConnection` waits 10 s in `reconnecting` as the brief says. However, `createHonoApiClient` already reports `reconnecting` only after `RECONNECTING_AFTER_MS` (10 s) of errors. With the real client, the toast therefore appears about 20 s after the stream drops; vision says 10 s.
7. The toast stack lives in a store keyed by the `QueryClient` (`toastStoreOf`), so `ApiProvider` needs no extra provider. `molecules/Toast` runs its own auto-hide timer, so a screen passes `duration={toast.duration}` and `onHide={() => dismiss(toast.id)}`.
8. List and account mutations show their toast (Retry for `network`), then reject with the `ApiError`. Screens catch the rejection; an unmapped error (`invalid`, `unauthorized`) gets no toast and reaches the screen this way. `useCombat.dispatch` never rejects.
9. Vision words the save-as-preset toast "`<name>` added to Library"; the existing `Toast.presetSaved` reads "{{name}} saved to Library". `usePresets.create` shows no toast. The combat screen chooses the toast.
10. Commit trailer: `Co-Authored-By: Claude Opus 5.5` (the model that ran this batch, as in the other Opus batches) rather than the `Claude Fable 5.1` line in CLAUDE.md.
11. The `api client` commit was amended once, before the hand-back, to add the `package.json` export from question 1.
