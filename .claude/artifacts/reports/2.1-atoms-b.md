## Questions

- NumberField: the brief lists a `size` prop, but `NumberField.dc.html` has no Sizes group and its `number` maker ignores size (always 68 high, value 32). No `size` prop was added. Should NumberField have S/M/L?
- NumberField: the page shows no negative values and no error or disabled cell. Sign entry is accepted only when `min < 0`. `error` (red border, alert icon and message, as in the page's shared `base()`) and `disabled` are covered by Extra stories.
- NumberField: `LIMITS` is not imported because packages/ui does not depend on @combat-planner/domain yet. Defaults `min = 0`, `max = 999` and the error text "From 1 to 999" are the page's numbers written as literals. Switch to `LIMITS` once the dependency exists.
- NumberField clamping: a value above `max` is clamped while typing, and so is a negative value below `min`. A positive value below `min` (for example `0` with `min = 1`) is clamped on blur, so a value like 15 can still be typed when `min` is 10. ArrowUp/ArrowDown step by `step` and clamp.
- Checkbox/Radio: the pages show the mark only. `label` is optional; without it the input takes `aria-label` (stories pass the translated "Select"). With a label, the root is at least 44 high. The label text style (Rubik 16/500, gap 12) is not on the page; the row typography belongs to CheckList/RadioList.
- Checkbox: the round condition colour comes from a `condition: ConditionName` prop that maps to `--cp-condition-<name>-text`. No raw colour prop was added. `indeterminate` and `description` are not built because the page has neither.
- SearchField: clicking × calls `onChange('')`, then `onClear?.()`, then focuses the input. The component reads the default placeholder "Search" and the × label "Clear search" from its own `SearchField` namespace.
