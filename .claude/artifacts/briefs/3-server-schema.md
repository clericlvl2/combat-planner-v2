## Units, in this order, one commit each

Subjects `feat(api): <unit>` for the first three, `feat(server): server main`
for the last.

1. `schema`: `packages/api/src/db/schema.ts` (Drizzle, SQLite): Better Auth
   tables (`user`, `session`, `account`, `verification`, generated with
   Better Auth's CLI or written per its Drizzle adapter docs for the installed
   version, with `user.language` as an extra column defaulting to `en`);
   `combats` (`id`, `ownerId`, `document` JSON text holding the domain
   `Combat`, `version`, `title`, `status`, `color`, `lastPlayedAt`,
   `createdAt`, `updatedAt` mirrored from the document for list sorting);
   `action_log` (`combatId`, `seq` autoincrement per combat, `actionId`
   unique per combat, `action` JSON, `author` JSON `Viewer`, `at`, `patch`
   JSON or null, `undoneBy` or null); `players` (`combatId`, `playerId`,
   `displayName`); `presets` (`id`, `ownerId`, fields of the domain `Preset`,
   `createdAt`); `tags` (`id`, `ownerId`, `name`, `nameLower` unique per
   owner); `preset_tags` (`presetId`, `tagId`); `settings` is `user.language`.
   `packages/api/src/db/index.ts`: `openDatabase(path)` with `better-sqlite3`,
   `PRAGMA journal_mode = WAL`, `foreign_keys = ON`, returning the Drizzle
   instance and a `close()`; `packages/api/drizzle.config.ts`.
2. `migrations`: `packages/api/drizzle/` generated by `drizzle-kit generate`
   from the schema (committed SQL and journal); `runMigrations(db)` in
   `packages/api/src/db/migrate.ts` using Drizzle's migrator; a test
   `packages/api/test/db.test.ts` that migrates a temporary file database,
   inserts one row per table, and reads it back.
3. `client-hono`: `packages/api/src/hono-client.ts`: `createHonoApiClient({
   baseUrl, fetch?, eventSource? })` implementing `ApiClient` from
   `client.ts` over `hono/client` (`hc<AppType>`) for every REST method and
   `EventSource` for `combats.subscribe`, `play.subscribe` and `connection`
   (`'connected'` on `open`, `'reconnecting'` 10 s after `error` without
   `open`, `'offline'` with no stream; `Last-Event-ID` is sent by the browser;
   on reconnect the client refetches when the document version is behind, per
   vision Data flow 13). Errors map to `ApiError` with `status` and `code`
   (`409 → 'version'`, `401 → 'unauthorized'`, `403 → 'forbidden'`, `404 →
   'notFound'`, `400/422 → 'invalid'`, no response → `'network'`). Routes that
   do not exist yet (phases 3-actions/live/rest) are called by their planned
   paths from the plan block; the type `AppType` is extended as those batches
   land, so this file compiles against the current `AppType` with the
   not-yet-existing paths typed through a local `PlannedRoutes` interface that
   the later batches delete. A test `packages/api/test/hono-client.test.ts`
   with a stub `fetch` asserting the error mapping and the `{ version }`
   result of `dispatch`.
4. `server main`: `apps/server/src/main.ts` reads `PORT` (3000),
   `DATABASE_PATH` (`data/combat-planner.db`, directory created), 
   `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `LINK_SECRET`,
   `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET`, `GITHUB_CLIENT_ID`/
   `GITHUB_CLIENT_SECRET` (optional), opens the database, runs migrations,
   builds the API app with `{ db, env }` and serves static files from
   `apps/web/dist`; `createApiApp` in `packages/api/src/app.ts` takes `{ db,
   env }` and keeps `/health` (the phase-0 `/events` tick route is removed
   together with `events.ts` and its tests; `apps/web` keeps proxying `/api`);
   `.env.example` at the repository root listing every variable with a
   comment-free placeholder value; `apps/server/src/app.test.ts` starts the
   app on a temporary database and asserts `/api/health` 200 and that a second
   start on the same file is idempotent (migrations already applied).
