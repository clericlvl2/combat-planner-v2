## Units, in this order, one commit each

1. `playerEvents` (`feat(ui): playerEvents`):
   `packages/ui/src/screens/PlayerView/playerEvents.ts` — a pure function
   `playerEvents(previous, next, playerId)` that derives the DM events vision
   lists (restart, clear, own hero released by the DM, own hero removed,
   a chosen hero just taken) from two consecutive player documents; unit
   tests in `packages/ui/test/screens/playerEvents.test.ts`, one per event and
   one for «no event» on an ordinary update.
2. `Heroes` (`feat(ui): Heroes`): `packages/ui/src/screens/Heroes/` — display
   name (`TextField`, `LIMITS.displayName`, asked once), `CheckList` of every
   Hero with own heroes checked and «You», others locked «<Name> is playing»;
   Join on the first visit, Done afterwards, disabled until a name and one
   hero; check → `claimUnit`, uncheck own → `releaseUnit` through
   `play.dispatch`; a hero taken while open → toast and the row locks; no
   header menu. Own stories file (free names).
3. `TurnOrder` (`feat(ui): TurnOrder`): `packages/ui/src/screens/TurnOrder/` —
   `PlayerHeader` (read-only copy of the combat header, ⋯ menu with Heroes);
   setup banner «Waiting for the DM to start the combat»; «No units yet»
   after Clear; `PlayerRow` list per the visibility table; own rows expand
   (conditions via `ConditionPicker`, HP history via `HpHistory` with the
   history reversed, note, Edit via `UnitForm` without tabs with `lockRole`,
   ⋯ Release claim); tap own HP → `NumpadSheet` without Set Max, then
   `useHpFlash` on the row; tap own initiative → `InitiativePopover`; only
   the actions vision marks «Player» are sent. Own stories file (free names).
4. `PlayerView` (`feat(ui): PlayerView`): `packages/ui/src/screens/PlayerView/PlayerView.tsx`
   switches between Heroes (first visit, menu Heroes, or no hero held after a
   release or removal) and TurnOrder; shows `playerEvents` as toasts; on
   `ended` switches to `LinkExpired` or `CombatDeleted` (with the title); a
   first load with `network` shows `CantReachServer` with Try again; the
   interface language is the DM's (`useCombat` `language`). Stories file
   `PlayerView.stories.tsx` with every `PV-F*` step the script requires.
